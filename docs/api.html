fnframes

The frames an HTTP/2 request is written as: the connection preface, this side's settings, and the HEADERS and DATA frames of the exchange. The connection is a fresh one, so the field section is encoded against the static table alone, which is what a first request on a connection looks like.

letlimits

The bounds a client uses when none are given: a 64 KiB head, 256 fields, and a 32 MiB body. No client of the common ones bounds a body by default; a library that returns a Response with the whole body in memory has to, or one answer can exhaust the process. 32 MiB covers the API payloads a buffered call is for; anything larger is read as a Stream, which is not bounded.

let limits : Limits

letredirects

How many redirects are followed when nothing else is said: reqwest's and requests' 10. A host that hands the redirect to its own stack follows as many as it allows; this is the number requests say.

let redirects : Int32

lettimeout

How long a request may take when nothing else is said, in milliseconds: httpx's 5 seconds.

let timeout : Int32

fnwire

The octets an HTTP/1.1 request is written as, for a caller that wants to see them: the head with its framing, then the body. A body produced while the request goes out is not read here — taking its pieces would spend them — so only the head is written, with the framing that says a body follows. Refused::Url for a URL no request can name, and the state machine's own refusal for a field it cannot write.

fn wire(@method.Method, StringView, query? : Array[(String, String)], headers? : Array[(String, String)], body? : Body) -> Wire raise

typeClient

An HTTP client over the host's fetch. base_url is the prefix relative URLs are joined to, as the client the other host has joins them. headers go on every request. timeout bounds each request, redirects included; None waits for ever. redirects caps how many are followed; 0 follows none. credentials is what the host may do with its cookies. limits bounds a buffered response. The host owns the connections, the cookie store, the proxy settings and the content codings, so there is no pool, jar or proxy here: close has nothing to close.

type Client
fn Client::close(Self) -> Unit

Close every connection the client keeps.

fn Client::new(base_url? : String, headers? : Array[(String, String)], timeout? : Int32?, redirects? : Int32, http2? : Bool, compression? : Bool, http3? : Bool, idle? : Int32, h2c? : Bool, limits? : Limits, jar? : Jar, proxy? : Proxy, tls? : @tls.Client) -> Self raise Refused

A client. base_url is the prefix relative URLs are joined to, as httpx joins them: its path is kept, so /users under https://a.example/api is https://a.example/api/users. headers go on every request. timeout bounds each request, redirects included; None waits for ever. redirects caps how many are followed; 0 follows none. http2 offers HTTP/2 by ALPN; h2c speaks HTTP/2 with prior knowledge over http, where there is no ALPN to ask. compression asks for gzip or deflate and decodes what comes back, as httpx and reqwest do; a request that names its own accept-encoding gets the body as sent. http3 speaks HTTP/3 over QUIC where it can, and falls back to TCP for an origin that does not answer on the datagram, as a browser's Alt-Svc does without the cache. limits bounds what a buffered response may hold. jar keeps cookies across requests. proxy sends the connection through an HTTP or SOCKS5 proxy. tls judges servers' certificates, the Mozilla roots when not given; its ALPN list is set by http2.

structLimits

What a client reads of a response before it refuses it. head bounds the status line and header block, fields the number of header fields, and body the body as it arrives, before any content coding is undone. The body bound is checked as the octets come in, so a server that would send more is stopped early rather than after the allocation.

structProxy

A proxy a client sends its connections through. http and https are the CONNECT method of RFC 9110 §9.3.6 — an https proxy speaks TLS to the proxy itself — and socks5 is RFC 1928, with the host sent as a name so the proxy resolves it.
